# AGENTS.md

**`PROMPT.md` is the authoritative product spec — read it fully before changing behavior.** This is a React + TypeScript + Vite + Tailwind CSS v4 F1 dashboard. All data comes live from the Jolpica F1 API (`https://api.jolpi.ca/ergast/f1/`). Never hardcode or mock F1 data ("DO NOT CHEAT" section of the spec).

## Commands

- `npm run dev` — Vite dev server (port 5173)
- `npm run build` — `tsc -b` typecheck + production build to `dist/`
- `npm run preview` — serve the production build (port 4173)
- `node scripts/build-circuits.mjs` — regenerates `src/lib/circuitTracks.ts` (bundled circuit SVG polylines). One-time network fetch from the MIT-licensed `bacinger/f1-circuits` GitHub dataset (`https://raw.githubusercontent.com/bacinger/f1-circuits/master/circuits/<id>.geojson`); the mapping `Ergast circuitId → dataset id` lives in the script. Re-run only to add/refresh tracks; the generated file is committed.

No lint/test tooling is configured; `tsc -b` is the verification gate. Run it before finishing.

## shadcn/ui

The app uses shadcn/ui (Radix base) on top of the F1 design system. `components.json` at the root; primitives live in `src/components/ui/` (button, card, badge, table, skeleton, separator, sheet, scroll-area, progress, tooltip, select) and `cn()` in `src/lib/utils.ts`. Add components via `npx shadcn@latest add <name>` (registry style is `radix-nova`; note `--base radix` is NOT a valid flag).

- **Theming**: `src/index.css` keeps the app's own `@theme` tokens (`accent`, `muted`, `surface`, `line`, …) as the source of truth for the F1 utilities (`text-muted`, `bg-accent`, …). The shadcn `@theme inline` block deliberately does NOT remap `--color-accent`/`--color-muted` (avoids clobbering the F1 tokens); shadcn's `:root` vars (`--background`, `--card`, `--primary`, `--border`, …) are set to the F1 palette in hex. The app is dark-only; the default `.dark` block was removed.
- **Migration scope**: Refresh/Retry/hamburger buttons → `Button`; status chips + round badges + FL tag → `Badge`; constructor points bar → `Progress`; loading states → `Skeleton`; section rules → `Separator`; mobile nav → `Sheet` drawer (replaces the old pills); sidebar nav → `ScrollArea`. Hero (`RaceStatusCards`), `StatStrip`, `SeasonTimeline`, `Countdown`, podium rows, `SectionHeading` and table row internals stay custom F1 compositions that compose shadcn primitives.
- **TooltipProvider wraps the whole app** in `App.tsx` (required for the Refresh tooltip).

## Architecture

- `src/lib/api.ts` — the only place that talks to the API. Raw `fetch()` with timeout + abort, per-endpoint fetchers, and normalization of raw Jolpica JSON into domain types. Do not add `fetch()` calls in components. `request()` auto-retries **transient** failures (HTTP 429/5xx, timeouts, network errors) up to 2 extra times with backoff (400ms→800ms); 4xx (except 429) and aborts are never retried. `ApiError` carries a `status` field for the retry classifier. `fetchSeasonResults` staggers its 6-at-a-time chunks by 120ms.
- `src/lib/types.ts` — normalized domain types.
- `src/lib/format.ts` — all display formatting + missing-value handling. Missing data renders as `N/A` or `--`; the UI must never show `undefined`/`null`/`NaN`/`[object Object]`.
- `src/lib/useDashboard.ts` — data state hook: season + round selection state. `seasonId` is `'current'` (live season) or a year string from `seasonYears` (current down to `SEASON_FLOOR = 2000`); `round: number | null` where `null` follows the season's last completed round. The featured race is `round ?? lastRace.round` and the round-scoped slices (`results`, `qualifying`, `pitStops`) fetch `/{season}/{featuredRound}/{results,qualifying,pitstops}.json` — **only when the featured round has already run**; upcoming/future rounds skip those fetches and set the slices to `ready/null` so sections show a "hasn't taken place yet" empty-state (driven by `featuredUpcoming`, computed against `now`). `seasonResults` fetches every completed round (chunked 6-at-a-time via `allSettled`, partial success OK) and feeds Progression + Head-to-Head. In-memory cache keyed per context (`schedule:2025`, `drivers:2025`, `results:2025:3`, `seasonResults:2025`) so season/round switches and Refresh are instant; Refresh clears the cache **and resets `now`** (so last/next race boundaries recalc) to force a network refetch (spinner + `UPDATED` timestamp must still update). Per-slice retry; derived `lastRace`/`nextRace`, `seasonComplete` (no upcoming rounds), and `championDriver`/`championConstructor` (standings P1) feed the hero's Season Summary / Championship Status panels.
- `src/lib/nav.ts` — nav model (`NAV_GROUPS` with target section ids) + section scroll targets; drives the sidebar and the mobile `Sheet` drawer. Items with a `route` field link to a hash route instead of a scroll anchor.
- `src/lib/router.ts` — tiny hash router (no dependency). Routes: `''`/`#/` → scroll dashboard, `#/standings` → `StandingsPage`, `#/driver/<driverId>` → `DriverPage`, `#/team/<constructorId>` → `TeamPage`. Optional query params `?season=YYYY&round=N` seed `useDashboard` (validated: year 2000..currentYear, round 1–60) and are mirrored back by App via `history.replaceState` whenever season/round/route change — the URL always reflects app state. `useHashRoute()` returns `{ route, params }` and reacts to `hashchange`. Sidebar anchors are handled programmatically (`scrollIntoView` on the target id, retried via rAF after a cross-route switch) so nav works from either route; section anchors do NOT rewrite the hash (params survive).
- `src/lib/circuitTracks.ts` — GENERATED by `scripts/build-circuits.mjs`; maps Ergast `circuitId` → projected 0–100 SVG polylines (`d`, `start`, `lengthM`). `CircuitTrack.tsx` renders it; `Circuit.tsx` + the hero thumbnail use it. Missing circuits (e.g. Korea/India/Valencia) fall back to details-only.
- `src/components/` — presentational modules: `Sidebar` (fixed `sticky top-0 h-screen` sidebar + `MobileNavSheet` drawer + `useScrollSpy`/`useNavActive` active-state. Scroll-spy is a single rAF-throttled scroll handler; clicking a nav item sets a manual active that clears on `scrollend` + 2.5s fallback; the active bar uses `duration-75` so the red marker snaps without flicker/fade-creep), `Header` (slim `TopBar` with season+round `Select`s via `Selectors.tsx` — canonical shadcn/Radix usage: always `<SelectValue/>`, `latest` is a real item labeled `LATEST`, round items are single truncating spans with the last-completed dot gold and the next race red; the season `Select` de-dupes the current year — Refresh `Button` + `UPDATED HH:MM:SS`; `viewLabel` maps dashboard sections plus `standings`/`driver`/`team`), `RaceStatusCards` (hero: dominant FEATURED RACE panel — podium when the selected round has run, else event details + countdown, plus a circuit-map thumbnail that is also passed `nextTrack`/`driverRows`/`constructorRows` — beside a context panel: when a past round is selected it shows a NEXT EVENT panel (next race name/countdown + circuit map + compact `WeekendSchedule`); when an upcoming round is selected it shows `ChampionshipStatus` with top-3 drivers and constructors; `SeasonSummary` when the season is complete; the left-panel label is `Race Result` / `Next Event` (only when the featured round IS the next race) / `Upcoming Round`), `StatStrip` (with season-progress band), `Standings` (`DriverTable`/`ConstructorTable` rows navigate to detail routes when `onSelectDriver`/`onSelectConstructor` handlers are passed), `LastRaceResults` (with prev/next round `Button`s), `FastestLap` (full-width banner with `text-6xl/7xl` numeral), `Qualifying` (Q1/Q2/Q3 table), `PitStops` (per-driver stop breakdown merged with the results slice), `Progression` (hand-rolled SVG cumulative constructor points), `HeadToHead` (two-driver Select comparison grid; optional `defaultA`/`defaultB` preconfigure a pairing and `onSelectDriver` makes rows link out), `WeekendSchedule` (FP1/FP2/FP3/SQ/SPR/QUAL strip — `compact` variant used in the hero; renders `date` directly and `N/A` time when the API omits session times, which it does for older seasons), `DriverPage` (header + per-round results table + cumulative `PointsChart` + Head-to-Head vs the driver's teammate), `TeamPage` (header + clickable driver cards + combined per-round table + `PointsChart`), `PointsChart` (shared single-series SVG sparkline), `Visualizations` (full-width interactive `SeasonTimeline` — rounds are `<button aria-pressed>` that select a round; the last-completed dot is gold, next is red, legend lists `Last completed`), `Countdown`, and `Skeleton`/`ErrorState` primitives. Red accent is used only as a signal (P1, active nav, labels, hairline rules, hero wash) — sections must not read as a wall of identical cards.

## Gotchas (verified against the API and browser)

- Jolpica shapes: results `Time.time` is full race time for the winner, otherwise a `+gap`. `FastestLap.rank === "1"` is the fastest lap holder (in the last-race results). Statuses are `Finished`/`Lapped`/`Retired`.
- Race dates are `YYYY-MM-DD` + `time` in UTC (`...Z`); parse as `${date}T${time}`. `lastRace`/`nextRace` are derived by comparing `start` to `now` — there is no finished/upcoming flag in the API.
- `current/last/results.json` returns the most recently completed round, so results/standings round numbers may differ from the calendar-derived last race. (The app fetches `/{season}/{round}/results.json` explicitly for the featured round, so it does not rely on this endpoint.)
- Jolpica round-scoped slices: `qualifying.json` (Q1/Q2/Q3 times) and `pitstops.json` (only populated from 2012 — pre-2012 rounds show an empty-state card) mirror `results.json`'s `Races[0]` shape. Pit stop rows carry only `driverId`, so `PitStops.tsx` merges them against the results slice for driver/team info. `seasonResults` is derived by fetching each completed round's results (chunked 6-at-a-time) — it is the engine for Progression + Head-to-Head and is cached per season.
- **Jolpica rate-limits concurrent bursts** — firing 6+ requests at once intermittently returns `429`. `request()`'s retry-with-backoff absorbs these (verified: 8 parallel requests, the 429'd one succeeded on retry 2). Future/upcoming rounds never hit the round-scoped endpoints (see `featuredUpcoming`), which keeps bursts small.
- Future-round round-scoped responses come back `200` with an empty `raceName`/`date`, so `normalizeRace` returns `null` and the fetchers resolve `null` — the app avoids relying on this by skipping the fetches entirely for upcoming rounds.
- Standings tables default to the top 12 (`DriverTable limit`, `LastRaceResults maxRows`); the `/standings` route renders every position (`Full Timing` header). `StandingsPage` reuses `DriverTable`/`ConstructorTable`/`LastRaceResults` with `limit`/`maxRows` passed.
- **Sticky table headers**: tables use `border-separate` (sticky `tr` fails with `border-collapse` in Chromium) and must NOT be wrapped in `overflow-x-auto` OR `overflow-hidden` (either wrapper becomes the scroll container and kills sticky). The shadcn `Table` component renders its own `overflow-x-auto` wrapper, so the standings tables use a bare `<table>` + the shadcn `TableHead`/`TableCell`/`TableRow`/`TableBody` subcomponents; only the LastRaceResults table uses the full `Table` (its wrapper provides the mobile horizontal scroll — it has no sticky header).
- **Responsive**: driver names in tables are capped with `max-w-[7.5rem]` truncation (9.5rem constructor cap) and the driver code column is hidden below `sm`; POS/WINS cells use `px-2 sm:px-4`; the next-race countdown row uses `flex-wrap` — all required to avoid horizontal page overflow at 320px. Decor badges that only add width on tiny screens are hidden below `sm`: standings `GAP` column, `LEADER` badge, hero `WINNER` badge; the hero grid panels and title use `min-w-0` + a `sm:`-scaled title so the grid never grows to its content min-width. The TopBar's two `Select`s use `max-w`/`line-clamp` triggers (round items truncate; the round trigger shows `LATEST` when following the last race); the `viewLabel` title is hidden below `sm` and the `UPDATED` stamp below `lg` so the bar stays one row at 320px. **The TopBar is a fixed `h-14` (56px) bar** (`flex h-full items-center`, no vertical padding) — the `top-14` (56px) sticky pins must not change, and any content height change must not break the 56px pin alignment (sticky headers sit flush at the bar's bottom).
- Sticky pins at `top-14` (56px) below the fixed TopBar; a sticky cell can never leave its containing table's bounds (standard CSS) — a scroll-to-max test will show it "unstick" once the table scrolls past, which is expected.

## Visual system (spec §4–§6)

Dark palette via Tailwind v4 `@theme` tokens in `src/index.css`: bg `#0F1115`, bg-secondary `#161920`, surface `#1E222D`, surface-2, accent `#E10600`, text `#E1E6ED`, muted `#8C96A6`, gold/silver/bronze (podium), good/warn/error, borders `rgba(255,255,255,0.08)` via `line`/`line-strong`. shadcn maps its `:root` CSS vars onto the same palette (`--background`/`--card`/`--primary`/`--border`/…). Broadcast-art direction: red accent is only a signal, uppercase `label`/`label-lg` kickers (`R11`, `LAP`, `START TIME`, `UPDATED`), `mono-num`/`tabular` utilities for all numerals, `main-wash`/`hero-wash` background washes, no neon/glassmorphism/cyan/fluorescent-green.
