# AGENTS.md

**`PROMPT.md` is the authoritative product spec — read it fully before changing behavior.** This is a React + TypeScript + Vite + Tailwind CSS v4 F1 dashboard. All data comes live from the Jolpica F1 API (`https://api.jolpi.ca/ergast/f1/`). Never hardcode or mock F1 data ("DO NOT CHEAT" section of the spec).

## Commands

- `npm run dev` — Vite dev server (port 5173)
- `npm run build` — `tsc -b` typecheck + production build to `dist/`
- `npm run preview` — serve the production build (port 4173)
- `node scripts/build-circuits.mjs` — regenerates `src/lib/circuitTracks.ts` (bundled circuit SVG polylines). One-time network fetch from the MIT-licensed `bacinger/f1-circuits` GitHub dataset (`https://raw.githubusercontent.com/bacinger/f1-circuits/master/circuits/<id>.geojson`); the mapping `Ergast circuitId → dataset id` lives in the script. Re-run only to add/refresh tracks; the generated file is committed.

No lint/test tooling is configured; `tsc -b` is the verification gate. Run it before finishing.

## shadcn/ui

The app uses shadcn/ui (Radix base) on top of the F1 design system. `components.json` at the root; primitives live in `src/components/ui/` (button, card, badge, table, skeleton, separator, sheet, scroll-area, progress, tooltip, select) and `cn()` in `src/lib/utils.ts`. Add components via `npx shadcn@latest add <name>` (registry style is `radix-nova`; note `--base radix` is NOT a valid flag).

- **Theming**: `src/index.css` keeps the app's own `@theme` tokens (`accent`, `muted`, `surface`, `line`, …) as the source of truth for the F1 utilities (`text-muted`, `bg-accent`, …). The shadcn `@theme inline` block deliberately does NOT remap `--color-accent`/`--color-muted` (avoids clobbering the F1 tokens); shadcn's `:root` vars (`--background`, `--card`, `--primary`, `--border`, …) are set to the F1 palette in hex. The app is dark-only; the default `.dark` block was removed.
- **Migration scope**: Refresh/Retry/hamburger buttons → `Button`; status chips + round badges + FL tag → `Badge`; constructor points bar → `Progress`; loading states → `Skeleton`; section rules → `Separator`; mobile nav → `Sheet` drawer (replaces the old pills); sidebar nav → `ScrollArea`. Hero (`RaceStatusCards`), `StatStrip`, `SeasonTimeline`, `Countdown`, podium rows, `SectionHeading` and table row internals stay custom F1 compositions that compose shadcn primitives.
- **TooltipProvider wraps the whole app** in `App.tsx` (required for the Refresh tooltip).

## Architecture

- `src/lib/api.ts` — the only place that talks to the API. Raw `fetch()` with timeout + abort, per-endpoint fetchers, and normalization of raw Jolpica JSON into domain types. Do not add `fetch()` calls in components. `request()` auto-retries **transient** failures (HTTP 429/5xx, timeouts, network errors) up to 3 extra times with backoff (400ms→800ms→1600ms); 4xx (except 429) and aborts are never retried. `ApiError` carries a `status` field for the retry classifier. `fetchSeasonResults` staggers its 6-at-a-time chunks by 120ms. `fetchLaps` pages `laps.json` 100 **timing rows** per request (`MRData.total` counts timing rows, not laps — a full race is ~15 sequential requests).
- `src/lib/types.ts` — normalized domain types. `Driver` carries `permanentNumber: string | null` (Jolpica supplies it for every driver; the champion races #1, so it reflects the number actually raced).
- `src/lib/format.ts` — all display formatting + missing-value handling. Missing data renders as `N/A` or `--`; the UI must never show `undefined`/`null`/`NaN`/`[object Object]`. `driverNumber(driver)` returns the permanent number or `null` (never `N/A`). `raceDateRange(race)` renders a weekend as `21 AUG – 23 AUG` (first session date → race date, single date when the API omits session dates for older seasons).
- `src/lib/useDashboard.ts` — data state hook: season + round selection state. `seasonId` is `'current'` (live season) or a year string from `seasonYears` (current down to `SEASON_FLOOR = 2000`); `round: number | null` where `null` follows the season's last completed round. The featured race is `round ?? lastRace.round` and the round-scoped slices (`results`, `qualifying`, `pitStops`) fetch `/{season}/{featuredRound}/{results,qualifying,pitstops}.json` — **only when the featured round has already run**; upcoming/future rounds skip those fetches and set the slices to `ready/null` so sections show a "hasn't taken place yet" empty-state (driven by `featuredUpcoming`, computed against `now`). The heavy fetches are staggered so the initial burst stays small: the lighter round slices fire first, `laps` starts ~300ms later and `seasonResults` ~600ms later (a `delayMs` field per def). `seasonResults` fetches every completed round (chunked 6-at-a-time via `allSettled`, partial success OK) and feeds Progression + Head-to-Head. In-memory cache keyed per context (`schedule:2025`, `drivers:2025`, `results:2025:3`, `seasonResults:2025`) so season/round switches and Refresh are instant; Refresh clears the cache **and resets `now`** (so last/next race boundaries recalc) to force a network refetch (spinner + `UPDATED` timestamp must still update). Per-slice retry; derived `lastRace`/`nextRace`, `seasonComplete` (no upcoming rounds), and `championDriver`/`championConstructor` (standings P1) feed the hero's Season Summary / Championship Status panels.
- `src/lib/nav.ts` — nav model (`NAV_GROUPS` with target section ids) + section scroll targets; drives the sidebar and the mobile `Sheet` drawer. Items with a `route` field link to a hash route instead of a scroll anchor. `NAV_GROUPS` is the pair (`Races` id `dashboard`, target `overview` / `Standings` route `/standings`) plus ONE unlabeled flush sub-nav: Overview, Calendar, Race Data, Fastest Lap, Lap Chart, Circuit, Watch Live (the pair id `dashboard` exists so it never collides with the standings sub-nav's Race Archive item, which owns id `races`). `STANDINGS_GROUPS` is the sub-nav shown on `#/standings` (Drivers, Constructors, Progression, Head-to-Head, Race Archive, Watch Live) — its items scroll **within** the standings page, they never navigate to the dashboard. `navTargets()` returns the dashboard's non-route targets de-duplicated (`[overview, calendar, results, fastest, lapchart, circuit, watchlive]` — the pair Races and the Overview item both target `overview`, so the `Set` matters); `standingsTargets()` returns only the sub-nav's `page: 'standings'` targets (`[drivers, constructors, progression, headtohead, races, watchlive]`) — it must **not** include the pair's Races `overview` target, or the standings scroll-spy starts at `overview` and stays stuck on Races until the user scrolls.
- `src/lib/router.ts` — tiny hash router (no dependency). Routes: `''`/`#/` → scroll dashboard, `#/standings` → `StandingsPage`, `#/driver/<driverId>` → `DriverPage`, `#/team/<constructorId>` → `TeamPage`, `#/race/<round>` → `RacePage`. Optional query params `?season=YYYY&round=N` seed `useDashboard` (validated: year 2000..currentYear, round 1–60) and are mirrored back by App via `history.replaceState` whenever season/round/route change — the URL always reflects app state. `useHashRoute()` returns `{ route, params }` and reacts to `hashchange`. Sidebar anchors are handled programmatically (`scrollIntoView` on the target id, retried via rAF after a cross-route switch) so nav works from either route; section anchors do NOT rewrite the hash (params survive).
- `src/lib/flags.ts` — `countryFlag(country)` → emoji flag map for F1 host countries (AU/GB/IT/US/AE/…) or `null` for unknown countries (renders no flag).
- `src/lib/circuitTracks.ts` — GENERATED by `scripts/build-circuits.mjs`; maps Ergast `circuitId` → projected 0–100 SVG polylines (`d`, `start`, `lengthM`). `CircuitTrack.tsx` renders it; `Circuit.tsx` + the hero thumbnail use it. Missing circuits (e.g. Korea/India/Valencia) fall back to details-only.
- `src/components/` — presentational modules: `Sidebar` (fixed `sticky top-0 h-screen` sidebar + `MobileNavSheet` drawer + `useScrollSpy`/`useNavActive` active-state. Scroll-spy is a direct `scroll` handler (no rAF gate, so it can't get stuck in StrictMode dev) that computes the active section from `offsetTop <= scrollY + 120` (last section wins at the page bottom, so the bottom `Watch Live` section still activates); clicking a nav item sets a `manual` active that clears on `scrollend` + 2.5s fallback; the active bar uses `duration-75` so the red marker snaps without flicker/fade-creep. `Races` and `Standings` sit at the top of the nav as a side-by-side 2-column row with surface backgrounds (segmented pair; the pair labels are `justify-center`'d in their half-boxes); the row item of the page you're on stays pressed persistently (Races on the dashboard route, Standings on `#/standings` **and** the detail routes — `NavList`'s `rowPressed` keys off `navMode`, independent of the section scroll-spy, so the pair shows the current menu while the sub-nav shows the current section) and lifts to `bg-surface-hover`, while active non-row items get `bg-surface/60` (idle row is `bg-surface`, idle non-row `text-muted hover:bg-surface/60`). The red left bar renders **only on sub-nav (non-row) items** — the pair row buttons show no bar so their labels sit dead-center. Unlabeled groups get a small `mt-1` gap (both navs are pair + flush unlabeled sub-nav, so the Watch Live item sits tight under Circuit); labeled groups would use `mt-4` but none remain. The dashboard nav is the pair plus a single flush sub-nav (Overview, Calendar, Race Data, Fastest Lap, Lap Chart, Circuit, Watch Live). On **every non-dashboard route** (`#/standings`, `#/driver/<id>`, `#/team/<id>`, `#/race/<round>`) the sidebar swaps to the standings sub-nav (Drivers, Constructors, Progression, Head-to-Head, Race Archive, Watch Live), so detail pages keep the same sidebar and their back button returns to the standings page; the `Races | Standings` pair stays visible in both modes. The manual active set by a nav click clears on `scrollend` + 2.5s fallback AND `App.tsx` calls `useNavActive`'s `resetManual` on every route change — so after landing on `#/standings` the TopBar label and sidebar highlight track the scroll-spy live (no lingering "STANDINGS" label). `NavItem.page` (`'dashboard' | 'standings'`) records each item's home page: the click handler smooth-scrolls when the target section exists on the current page, otherwise it rewrites the hash to the item's home (`#/` for dashboard items like `Races`, `#/standings` for sub-nav items) then scrolls. Content is split by page: the dashboard hosts only the Races content (`overview`, `calendar`, `results`, `fastest`, `lapchart`, `circuit`, `watchlive`), and the standings page hosts the six sub-nav sections (`drivers`, `constructors`, `progression`, `headtohead`, `races`, `watchlive`). `navTargets()` is `[overview, calendar, results, fastest, lapchart, circuit, watchlive]`; a second scroll-spy drives the sub-nav on the standings route via `standingsTargets()` (on detail routes the sub-nav shows no active item — `effectiveActive` is `driver`/`team`/`race`). `useNavActive()` exposes `manual` so the standings route can combine `manual ?? standingsSpy`, `Header` (slim `TopBar` with season+round `Select`s via `Selectors.tsx` — canonical shadcn/Radix usage: always `<SelectValue/>`, `latest` is a real item labeled `LATEST`, round items are single truncating spans with the last-completed dot gold and the next race red; the season `Select` de-dupes the current year — Refresh `Button` + `UPDATED HH:MM:SS`; `viewLabel` maps dashboard + standings sections plus `driver`/`team`/`race`), `RaceStatusCards` (hero: dominant FEATURED RACE panel — podium when the selected round has run, else event details + countdown, plus a circuit-map thumbnail that is also passed `nextTrack`/`driverRows`/`constructorRows` — beside a context panel: when a past round is selected it shows a NEXT EVENT panel (next race name/countdown + circuit map + compact `WeekendSchedule`); when an upcoming round is selected it shows `ChampionshipStatus` with top-3 drivers and constructors; `SeasonSummary` when the season is complete; the left-panel label is `Race Result` / `Next Event` (only when the featured round IS the next race) / `Upcoming Round`), `StatStrip` (with season-progress band), `Standings` (`DriverTable`/`ConstructorTable` rows navigate to detail routes when `onSelectDriver`/`onSelectConstructor` handlers are passed), `LastRaceResults` (with prev/next round `Button`s), `FastestLap` (full-width banner with `text-6xl/7xl` numeral), `Qualifying` (Q1/Q2/Q3 table), `PitStops` (per-driver stop breakdown merged with the results slice), `Progression` (hand-rolled SVG cumulative constructor points), `HeadToHead` (two-driver Select comparison grid; optional `defaultA`/`defaultB` preconfigure a pairing and `onSelectDriver` makes rows link out), `WeekendSchedule` (FP1/FP2/FP3/SQ/SPR/QUAL strip — `compact` variant used in the hero; renders `date` directly and `N/A` time when the API omits session times, which it does for older seasons), `DriverPage` (header + per-round results table + cumulative `PointsChart` + Head-to-Head vs the driver's teammate), `TeamPage` (header + clickable driver cards + combined per-round table + `PointsChart`), `StandingsPage` (hosts the six sub-nav sections on `#/standings`: `DriverTable`/`ConstructorTable` at all positions, `Progression`, `HeadToHead`, `RaceArchive` — clickable rows listing flag + race name + `raceDateRange` + P1/P2/P3 codes for every completed round, deep-linking to `#/race/<round>` — and `WatchLive`), `RacePage` (`#/race/<round>`: back button to `#/standings`, header card with flag/circuit/date range, full-grid `LastRaceResults` fed from `seasonResults`), `PointsChart` (shared single-series SVG sparkline), `Visualizations` (full-width interactive `SeasonTimeline` — rounds are `<button aria-pressed>` that select a round; the last-completed dot is gold, next is red, legend lists `Last completed`), `Countdown`, `DriverNumber` (renders `#<permanentNumber>` beside a driver's name in standings/podium/results/detail pages — returns `null` when the number is absent so old seasons never show `#N/A`; styled `mono-num` and only used inside driver-identity blocks, never next to numeric data columns), `WatchLive` (four external streaming cards linking out in new tabs — `pitsport.xyz`, `streamed.pk`, `ppv.to`, `acestrlms.pages.dev`, each card titled by its domain with a LIVE badge and an external-link icon; the footer hostname line was dropped since the card title carries the domain), and `Skeleton`/`ErrorState` primitives. Red accent is used only as a signal (P1, active nav, labels, hairline rules, hero wash) — sections must not read as a wall of identical cards.

## Gotchas (verified against the API and browser)

- Jolpica shapes: results `Time.time` is full race time for the winner, otherwise a `+gap`. `FastestLap.rank === "1"` is the fastest lap holder (in the last-race results). Statuses are `Finished`/`Lapped`/`Retired`.
- Race dates are `YYYY-MM-DD` + `time` in UTC (`...Z`); parse as `${date}T${time}`. `lastRace`/`nextRace` are derived by comparing `start` to `now` — there is no finished/upcoming flag in the API.
- `current/last/results.json` returns the most recently completed round, so results/standings round numbers may differ from the calendar-derived last race. (The app fetches `/{season}/{round}/results.json` explicitly for the featured round, so it does not rely on this endpoint.)
- Jolpica round-scoped slices: `qualifying.json` (Q1/Q2/Q3 times) and `pitstops.json` (only populated from 2012 — pre-2012 rounds show an empty-state card) mirror `results.json`'s `Races[0]` shape. Pit stop rows carry only `driverId`, so `PitStops.tsx` merges them against the results slice for driver/team info. `seasonResults` is derived by fetching each completed round's results (chunked 6-at-a-time) — it is the engine for Progression + Head-to-Head and is cached per season.
- **Jolpica rate-limits concurrent bursts** — firing 6+ requests at once intermittently returns `429`. `request()`'s retry-with-backoff absorbs these (verified: 8 parallel requests, the 429'd one succeeded on retry 2). Future/upcoming rounds never hit the round-scoped endpoints (see `featuredUpcoming`), which keeps bursts small.
- Future-round round-scoped responses come back `200` with an empty `raceName`/`date`, so `normalizeRace` returns `null` and the fetchers resolve `null` — the app avoids relying on this by skipping the fetches entirely for upcoming rounds.
- Standings tables default to the top 12 (`DriverTable limit`, `LastRaceResults maxRows`); the `/standings` route renders every position (`Full Timing` header). `StandingsPage` reuses `DriverTable`/`ConstructorTable`/`Progression`/`HeadToHead`/`RaceArchive`/`WatchLive` with `limit` passed for all positions; `RacePage` (`#/race/<round>`) reuses `LastRaceResults` with `maxRows` passed for a round's full grid (its `upcoming={false}`, since the Race Archive only lists completed rounds).
- **Sticky table headers**: tables use `border-separate` (sticky `tr` fails with `border-collapse` in Chromium) and must NOT be wrapped in `overflow-x-auto` OR `overflow-hidden` (either wrapper becomes the scroll container and kills sticky). The shadcn `Table` component renders its own `overflow-x-auto` wrapper, so the standings tables use a bare `<table>` + the shadcn `TableHead`/`TableCell`/`TableRow`/`TableBody` subcomponents; only the LastRaceResults table uses the full `Table` (its wrapper provides the mobile horizontal scroll — it has no sticky header).
- **Responsive**: driver names in tables are capped with `max-w-[7.5rem]` truncation (9.5rem constructor cap) and the driver code column is hidden below `sm`; POS/WINS cells use `px-2 sm:px-4`; the next-race countdown row uses `flex-wrap` — all required to avoid horizontal page overflow at 320px. Decor badges that only add width on tiny screens are hidden below `sm`: standings `GAP` column, `LEADER` badge, hero `WINNER` badge; the hero grid panels and title use `min-w-0` + a `sm:`-scaled title so the grid never grows to its content min-width. The TopBar's two `Select`s use `max-w`/`line-clamp` triggers (round items truncate; the round trigger shows `LATEST` when following the last race); the `viewLabel` title is hidden below `sm` and the `UPDATED` stamp below `lg` so the bar stays one row at 320px. **The TopBar is a fixed `h-14` (56px) bar** (`flex h-full items-center`, no vertical padding) — the `top-14` (56px) sticky pins must not change, and any content height change must not break the 56px pin alignment (sticky headers sit flush at the bar's bottom).
- Sticky pins at `top-14` (56px) below the fixed TopBar; a sticky cell can never leave its containing table's bounds (standard CSS) — a scroll-to-max test will show it "unstick" once the table scrolls past, which is expected.
- **Section DOM order must match its scroll-spy targets**: on the dashboard the `<section>`s in `App.tsx` must stay in `navTargets()` order; on the standings page the sections in `StandingsPage.tsx` must stay in `standingsTargets()` order. The scroll-spy iterates the target ids and reads each section's `offsetTop`, so reordering independently makes the red active bar highlight the wrong item. When adding/moving a section, update both the group list in `nav.ts` and the page JSX in the same relative order.

## Visual system (spec §4–§6)

Dark palette via Tailwind v4 `@theme` tokens in `src/index.css`: bg `#0F1115`, bg-secondary `#161920`, surface `#1E222D`, surface-2, accent `#E10600`, text `#E1E6ED`, muted `#8C96A6`, gold/silver/bronze (podium), good/warn/error, borders `rgba(255,255,255,0.08)` via `line`/`line-strong`. shadcn maps its `:root` CSS vars onto the same palette (`--background`/`--card`/`--primary`/`--border`/…). Broadcast-art direction: red accent is only a signal, uppercase `label`/`label-lg` kickers (`R11`, `LAP`, `START TIME`, `UPDATED`), `mono-num`/`tabular` utilities for all numerals, `main-wash`/`hero-wash` background washes, no neon/glassmorphism/cyan/fluorescent-green.
